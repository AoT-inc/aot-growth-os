# 검토 화면 (review-web)

사람이 결정할 것을 쉬운 말·간단한 그래프·원본 증거(그림 포함)로 보여 주고, **버튼으로 결정하게 하는 로컬 웹 화면**이다. 승인 CLI(`apps/daemon/src/approve.ts`)가 JSON과 해시만 찍어서 결정하기 어려운 문제를 푼다.
**화면 프로세스는 DB에 쓰지 못한다.** DB는 읽기 전용으로만 열고, 결정(승인·거절·다시 쓰게·취소·OTP 확인)은 승인 CLI와 같은 Unix 소켓으로 데몬의 승인 엔진에 보낸다. 검증과 기록은 엔진만 한다. 결정 버튼은 시작할 때 사람 행위자(`--actor`)를 주었을 때만 켜지고, 주지 않으면 보기 전용이다. 설계: [decision-delegation](../plans/decision-delegation.md) §2, [ADR-0016](../adr/0016-decision-delegation.md).

## 실행

```
npm run review-web -- --db instance/demo/review.db              # 데모 (아래 "데모")
npm run review-web -- --config instance/daemon.config.json       # 데몬 설정에서 DB·위치를 읽는다
npm run review-web -- --db instance/aot.db --port 8787 --evidence-root ~/Pictures/evidence
npm run review-web -- --config instance/daemon.config.json --actor <사람 행위자 id>    # 화면에서 결정하기 (데몬이 켜져 있어야 한다)
```

시작하면 `검토 화면(결정 가능 | 보기 전용): http://127.0.0.1:<포트>/?token=…` 를 **한 번만** 찍는다(토큰은 시작할 때마다 새로 만들고 다른 곳에 기록하지 않는다). 브라우저로 그 주소를 처음 한 번 열면 쿠키가 설정되고 토큰 없는 주소로 옮겨 가며, 이후 그 브라우저는 계속 본다. 기본 포트 8787, `--port 0` 이면 빈 포트.

| 인자 | 뜻 |
|---|---|
| `--db <경로>` | DB 파일. 없으면 데몬 설정의 `db_path` |
| `--config <파일>` | 데몬 설정 파일(`main.ts` 와 같은 것). 기본 `$AOT_DAEMON_CONFIG`, 없으면 `<인스턴스>/daemon.config.json` (있을 때만) |
| `--instance-dir <폴더>` | 인스턴스 폴더. 기본 설정의 `instance_dir` > `$AOT_INSTANCE_DIR` > (`--db` 만 줬으면 그 DB 가 있는 폴더) > `instance` |
| `--evidence-dir <폴더>` | 호스트 근거 저장소(`blob:sha256:` 본문). 기본 설정의 `registration_tools.evidence_dir` > `<인스턴스>/evidence` |
| `--policy-dir <폴더>` | 정책 보관소. 기본 설정의 `policy_store_dir` > `<인스턴스>/policies`. 승인 해시 계산에 현재 정책이 필요하다(없는 파일은 저장소 템플릿 `policies/default.yaml` 로 찾는다) |
| `--evidence-root <폴더>` | 증거 **파일**(그림)을 읽어도 되는 폴더. 여러 번 줄 수 있다. `measure --attach` 로 올린 파일이 있는 폴더를 알려 준다 |
| `--actor <id>` | 화면에서 결정할 **사람 행위자**. 없으면 `$AOT_ACTOR`, 그래도 없으면 보기 전용. 시작할 때 소켓으로 `whoami` 를 보내 사람인지 확인하고, 실패하면(사람이 아님·데몬이 꺼짐·응답 없음) 보기 전용으로 띄우고 터미널과 화면에 까닭을 알린다 |
| `--socket <경로>` | 승인 엔진 소켓. 기본 `$AOT_APPROVAL_SOCKET` > 데몬 설정의 `approval_socket` > `<인스턴스>/run/approval.sock` (승인 CLI 와 같은 기본값) |
| `--port <N>` | 포트 |
| `--host` | `127.0.0.1` 만 허용(다른 값은 거부) |

## 화면

모든 화면은 **결론이 먼저**다: 사람이 몇 초 안에 "무엇을 결정해야 하나"를 알 수 있게 한 줄 질문으로 시작한다 → 사실 2~3줄 → 이력 요약(최대 3줄) → 결정 버튼 → 접힌 "자세히". 내부 id·해시·상태 코드·ISO 시각·엔진 영문 문구·JSON 은 첫 화면에 내지 않고 접힌 "자세히" 안에만 둔다. **어느 화면에도 승인 CLI 명령을 찍지 않는다.**

| 주소 | 내용 |
|---|---|
| `/` 결정할 일 | 맨 위 "결정할 일 N건"(없으면 "지금 결정할 일이 없습니다"). 급한 순(만료 임박·업무를 막는 것 먼저) 한 줄 목록의 카드 전체가 링크다: 질문 + 핵심 사실 3줄(무엇 · 확인할 것 · 위험·기한) + 판정 배지(검증 통과/검증 실패 — 승인 불가/판정 보류). 제목 아래 한 줄에 종류별 개수, 목록은 "먼저"(바깥에 나가는 일·하루 이상 업무를 막는 일·3일 안에 만료)와 "이번 주 안에"로 나뉜다. 「무엇」은 실제로 일어날 일(대상·내용 미리보기, 정책은 바뀌는 규칙)이고 미리보기를 만들 수 없으면 "내용 미리보기 없음 — 자세히에서 원문 확인"이라 쓴다. 같은 사유로 멈춘 업무는 한 장으로 묶인다(예: 고객에게 나가는 작업 3건). 아직 제안이 없는 재편 신호도 "새 역할 제안서를 만들까요?" 카드로 올라온다. 그 아래 "AI가 처리함" 요약(위임이 있을 때만, 아래 `/delegated` 참고)과 "지켜보는 중" 한 줄 요약(시험 중, 결과 대기 실험, 반복 문제 역할) |
| 결정 상세 (`/approvals/<종류>/<id>`, `/batch/<묶음>`, `/products/<slug>`, `/effects`, `/experiments/<id>`, `/signals/<유형>`) | 한 틀: 질문(제목) → 한 문장 요약("바뀌는 것") → 배지·사실 3줄 → 이력 요약 → "결정하기" 상자 → 접힌 "자세히"(평가 계획·롤백 계획·증거 목록·정책 판정·엔진 원문 등). 못 하는 이유가 있으면 해당 버튼 대신 이유("승인 불가 — …") |
| `/result/<무작위 id>` 결과 | 결정을 보낸 뒤 303 으로 오는 화면(메모리에 10분). 결론 한 줄 → 다음에 할 일 → 접힌 자세히(엔진 원문). 묶음은 "3건 중 2건 반영, 1건 실패: 내용이 바뀜" 처럼 건별로 말한다 |
| 초안 승인 업무 (ADR-0015, `/approvals/task/<id>`, 묶음 `/batch/<묶음>`) | 고객에게 나가는 메일을 에이전트가 먼저 초안으로 쓰고, 사람이 **그 내용 그대로** 승인한다. 카드 「무엇」은 `받는 사람 N명 · 제목 '…' · 첫 줄 …`(메일이 여럿이면 `메일 K건 · 받는 사람 모두 N명 · 첫 제목 '…'`), 메일 모양이 아닌 초안은 `내용 미리보기 없음 — 자세히에서 원문 확인`. 「확인할 것」은 `받는 사람과 문구가 이대로 나가도 되는지`, 「위험·기한」에 `초안 N시간 뒤 만료`. 초안이 외부 입력(웹 페이지·고객 문의 등)의 영향을 받아 쓰였으면 배지 `외부 입력 영향 하에 작성됨`. 상세는 「보낼 내용」이고 결정하기 상자 위에 있다: 초안마다 받는 사람·참조·숨은 참조의 **정확한 주소**(이 화면은 로컬이고 쿠키로 보호되므로 가리지 않는다), 도메인별 인원 수, 제목, 본문 전문(`<pre>` 상자 안에서 스크롤, 자르지 않는다), 보내는 방법(도구·작업·대상), 기한. 본문 말고 payload 에 있는 **모든 필드**(`html` 은 이스케이프한 소스 글, `reply_to`, `headers`, `attachments` 정보, 모르는 키, 중첩 객체)도 `메일 본문 말고도 아래 항목이 함께 나갑니다` 아래에 이름과 값으로 그대로 보인다. 메일 모양이 아닌 초안도 필드마다 전부 보인다. 자세히에는 내용 해시 전체와 payload 원문 전체가 있다. 한 필드가 5만 자를 넘거나(합계 30만 자, 필드 400개), 글이 아닌 값(제어 문자·깨진 바이트)이거나, 비밀 가리기가 바꾸는 값이면 **다 볼 수 없는 초안**이다: 배지 `승인 불가 — 다 볼 수 없는 값이 있음`(비밀 가림은 아래 `가려진 값`), 이유가 있는 필드 목록, 질문 `다시 쓰게 할까요?`, 승인 버튼 없음 — 조용히 자르지 않는다. 결정하기 상자는 `승인` / `거절` / **`다시 쓰게`**(이유 필수, 초안을 버리고 에이전트가 다시 쓰게 함). 기한이 지난 초안은 승인 버튼 대신 `초안 기한이 지났습니다 — 다시 쓰게 해 주세요` 와 거절·다시 쓰게 버튼만 낸다(엔진도 승인을 거절한다). 초안이 있는 업무와 없는 업무는 한 장으로 묶지 않고, 초안 업무 묶음은 메일 수·받는 사람 수를 합쳐 보이며 묶음 승인에서 기한 지난 건은 뺀다. 질문은 메일 수로 센다(`고객 안내 메일 4통(받는 사람 8명)을 보낼까요?`, 업무 수는 자세히에만). 「위험·기한」은 `보내면 되돌릴 수 없음 · 초안 N시간 뒤 만료` 두 마디까지이고, 기한이 지난 건 수는 배지(`1통 기한 지남`)로 보인다. 엔진과 같은 가리기(`maskSecrets`, 값 모양 + 키 이름)로 가려지는 값이 있는 초안은 배지 `승인 불가 — 가려진 값이 있음` 과 한 줄 이유만 내고 승인 버튼은 없다(다시 쓰게 함). 이미 나갔거나(보냄) 전송 여부 불명·보내지 못함인 초안이 있으면 초안별 상태를 보이고 거절·다시 쓰게 버튼을 숨긴 채 전송 여부 카드로 안내한다(엔진도 거절한다). 가려진 값이 있거나 다 볼 수 없거나 이미 나간 초안이 있는 업무는 다른 업무와 묶지 않는다. AI가 승인했다가 사람에게 돌아온 업무(예: 위임이 멈춤)는 거절·다시 쓰게 버튼에 `이 일은 AI가 승인했던 일입니다 …같은 종류의 AI 처리가 멈추고…` 를 적는다 — 엔진이 사람의 거절·변경 요청도 취소처럼 그 위임을 멈추기 때문이다. 초안이 없는 고객 업무는 예전 문구 그대로 |
| `/trials/<id>` 시험 | 판정 한 줄("아직 판정 전 — 6건 중 3건 관측. 지금까지 통과율 100%로 기준(80%) 이상") → 통과율 대 기준선 그래프 하나 → 결정 버튼. 관측·비용 그래프는 자세히 안 |
| `/delegated` AI가 처리함 | 정책의 위임(ADR-0016) 안에서 AI가 대신 승인한 일의 **요약**이다. 결정이 아니다: 이런 일은 "결정할 일"에 올라오지 않는다. 맨 위 한 줄 "AI가 지난 24시간에 3건 처리함. 1건은 아직 나가지 않았고 취소할 수 있습니다", 건마다 카드 하나: 무엇을 누구에게(`메일 1통 '제목' → k***@example.com`, 주소는 가림) · 배지(나가기 전/나가는 중/나감/취소됨/사람이 결정할 일로 돌아옴/실패) · 언제 나감("50분 뒤 나감", "어제 나감") · 한 줄 "AI의 판단: …" · 아직 나가기 전이면 `취소` 버튼("취소하면 같은 종류의 AI 처리가 멈춥니다"). 위에 `위임 멈추기`(TOTP 없음; 멈추면 아직 나가지 않은 AI 승인도 효력을 잃고 사람이 다시 결정한다). 멈춰 있으면 `위임 다시 켜기`(OTP 6자리; 멈추기 전에 받은 AI 승인은 되살아나지 않는다). 7일 보관. 홈에는 같은 요약 중 최대 3건이 "AI가 처리함"으로 보인다 |
| `/watch` 지켜보는 중 | 할 일 없이 진행 중인 것 한 줄씩 |
| `/evidence` 증거 | "무엇을 보여 주는 증거인지" + 확인됨/미확인 + "외부 입력 — 지시 아님" 표시, 그림은 썸네일, 원문은 항목별 "원문" 접기. 상세는 본문(그림·텍스트)을 바로 보여 주고 메타는 자세히 안 |

### 화면에서 결정하기

결정 상자의 버튼. 결정마다 필요한 것만 나온다.

| 버튼 | 입력 | 설명 |
|---|---|---|
| `승인` | 없음 | 위험 변경이면 버튼 아래에 "승인 뒤 대기 시간이 지나면 OTP 코드로 한 번 더 확인해야 합니다" 한 줄 |
| `거절` | 접힌 "이유 남기기 (선택)", 500자 | 이유 없이도 된다 |
| `다시 쓰게` (초안 승인 업무) | 이유 필수, 1~500자(엔진 규칙) | 제안된 초안을 버리고 에이전트가 다시 쓰게 한다. 눌러야 이유 칸이 열린다 |
| `취소` | 없음 | 승인 뒤 대기 시간 중에만 |
| `OTP 확인` | 숫자 6자리(`inputmode=numeric`, `autocomplete=one-time-code`) | 대기가 끝난 위험 변경. 정책이 재인증을 요구할 때만 OTP 를 받는다(효과 확정의 "나가지 않았다" 포함) |
| `취소` (AI가 처리함) | 없음 | AI가 대신 승인했고 아직 나가기 전인 일. 취소하면 그 위임이 자동으로 멈춘다(해제는 `위임 다시 켜기`, OTP) |
| `위임 멈추기` / `위임 다시 켜기` | 다시 켜기만 OTP | `/delegated` 위쪽 |
| 그 밖 | 이유 필수 | 효과 확정(나갔다/나가지 않았다), 상품 반려·다시 검증, 실험 승격·끝내기, 조직 시험 정식 확정 |

묶음 버튼 하나는 묶음 안 결정 가능한 업무에 **차례로** 보낸다(엔진에 묶음 명령은 없다). 틀린 OTP 가 한 번 나오면 나머지 건은 보내지 않는다.

**화면에서 할 수 없는 결정**(파일이 필요하다)은 버튼 대신 "이 결정은 화면에서 할 수 없습니다" 한 줄을 낸다. 이 경우만 승인 CLI 를 쓴다(`apps/daemon/src/approve.ts`의 머리말 참고): 정책 배포(`approve policy --file <정책.yaml>`), 조직 재시험(`org retrial <제안 id> --file <평가 계획.json> --comment 사유`), 새 역할 제안(`org propose --type <업무 유형> --role <새 역할 slug>`).

**실패하면** 결과 화면이 사람 말로 알린다(엔진 응답의 `code` 로만 정한다. `code` 가 없거나 모르는 코드면 영어 문장을 짐작하지 않고 "처리하지 못했습니다" 한 줄. 영어 원문은 접힌 자세히에만 있다):

| 경우 | 첫 줄 | 다음에 할 일 |
|---|---|---|
| 내용이 바뀜 | 결정이 반영되지 않았습니다. 그 사이 내용이 바뀌었습니다. | 새 내용 보기 |
| 이미 처리됨/상태 다름 | 이미 다른 결정이 났습니다. | 결정할 일로 가기 |
| 전송이 시작됨 | 이미 보내기 시작해 거절·다시 쓰게를 할 수 없습니다. | 전송 여부 카드 |
| OTP 틀림/잠김 | OTP 코드가 맞지 않습니다. / 잠시 뒤 다시 하세요(5분). | 다시 하기 |
| 데몬 꺼짐 | 데몬이 꺼져 있어 보내지 못했습니다. 아무것도 바뀌지 않았습니다. | 다시 하기 |
| 응답 없음 | 결과를 확인하지 못했습니다. (자동 재시도 없음) | 상태 다시 보기 |
| 요청이 맞지 않음 | 요청이 맞지 않아 처리하지 못했습니다. | 새 내용 보기 |
| 그 밖 | 처리하지 못했습니다. | 새 내용 보기 |

### 이력 요약

결정 상세마다 최대 3줄: ① 어떻게 왔나("3일 전 정기 루틴이 만듦", "오너가 직접 만듦", "앞 업무 결과로 만듦", 실험의 업무면 실험 이름) ② 앞선 결정("다시 쓰게 1번('인사말을 짧게'), 지금 초안이 2번째", "한 번 거절된 뒤 다시 제안됨", "실행 2번 중 1번 실패") ③ 링크(증거 n건, 전송 여부 확인, 관련 상품, 앞 업무). 외부 URL 링크는 **사람이 입력한 값**(상품 저장소·환경 주소)만, http/https 만, 새 창·`rel="noopener noreferrer"` 로 연다. 에이전트·외부 입력에서 온 URL(증거 `source_url` 등)은 글자로만 보인다. 첫 화면(카드)에는 이력을 더하지 않는다.

결정에 쓰이는 해시는 승인 엔진의 `show`(읽기 전용 명령)가 계산한 값이라 CLI가 실제로 확인하는 해시와 같다. 화면에는 찍지 않는다.

### 위임 (AI가 처리함)

사람이 TOTP 로 배포한 정책의 `delegation` 안에서만 AI(`approval-delegate`)가 초안 승인 업무를 대신 승인한다(ADR-0016). 화면은 이를 **결정이 아닌 요약**으로 다룬다.

- 위임 승인이 지금도 유효한 업무(엔진 `show` 의 `approval.mandate_id`)는 홈의 결정 카드·묶음에서 빠진다. 상세 주소(`/approvals/task/<id>`)로 들어오면 "AI가 처리한 일입니다 — AI가 처리함에서 보세요".
- 위임이 멈추거나 철회·만료·정책 변경으로 효력을 잃으면 그 업무는 다시 결정 카드로 돌아오고, 「확인할 것」 줄이 "AI가 넘긴 이유: 위임이 멈추거나 바뀌어 사람이 다시 확인해야 합니다"로 바뀐다. AI가 사람에게 넘긴 업무도 같은 줄에 AI의 이유(`delegate_review.reason`, 한국어 한 줄)를 보인다.
- 읽는 것: `approval.mandate_id`(위임 승인 행), `delegate_review`, 엔진 `show`/`delegation status`. 쓰는 것은 다른 결정과 똑같이 버튼 → `POST /decide` → 소켓(`cancel`, `delegation pause|resume`)이다. 화면은 AI 결정 요청(`delegate_decide`)을 보낼 수 없다.
- 위임이 없는 정책에서는 홈·`/delegated` 가 "AI가 처리함"을 내지 않는다(`/delegated` 는 "지금은 AI에게 맡긴 일이 없습니다").
- 사람이 위임 승인을 취소하든 거절하든 변경을 요청하든, 엔진은 그 위임을 자동으로 멈춘다(응답에 `delegation_paused`). 다시 켜기는 사람 + TOTP 다.
- 정책 제안 카드(`/approvals/policy_version/<id>`)는 한도·규칙·승인 절차뿐 아니라 **`delegation`·`phone`·기억 만료 섹션**까지 비교한다. 위임을 넓히는 변경은 첫 줄에 `AI 위임 추가: 모든 작업, 하루 최대 1000건` 처럼(`classifyChange` 이유를 사람 말로) 나오고, 넓어지지 않는 위임 변경도 `AI 위임이 바뀝니다`로 나온다. `현재 정책과 같은 내용`은 모든 섹션이 같을 때만이다. 위임을 추가·확대하는 정책은 지금 정책이 `reauth_before_effect: false` 여도 배포(`release`)에 항상 TOTP 가 필요하다.
- 가짜 검토자(stub)는 시험용이다: 데몬 설정 `delegate_reviewer` 에 `{"kind":"stub"}` 을 두면 데몬이 시작을 거부한다(`verdict: "approve"` 면 적격한 모든 업무를 사람 없이 승인하기 때문). 시험 코드만 `parseDelegateReviewerConfig(value, { allowStub: true })` 로 연다. 운영 조립(`main.ts`)은 이 플래그를 주지 않는다.
- 실제 AI 검토자는 아직 없다(`DelegateReviewer` 포트와 stub 뿐): 그래서 운영에서 위임을 선언해도 AI 승인은 아직 일어나지 않고, 이 요약은 비어 있다. 데모(`scripts/review-web-demo.ts`)는 승인 행을 직접 심어 이 화면을 보여 준다.

## 보안 모델

신뢰 경계는 [trust-boundaries](../security/trust-boundaries.md) 를 따른다: DB 의 에이전트 출력·증거·외부 입력은 모두 신뢰하지 않는다.

- **DB 쓰기 없음, 결정은 소켓.** DB 는 `openDb({ readOnly: true })` 로 열어 SQLite 가 쓰기를 거부하고, 그 위에 쓰기 메서드(`run`·`exec`·`writeTx`)를 던지게 하는 껍질을 한 번 더 씌운다. 화면 안의 승인 엔진은 읽기 전용 DB 위에서 `list`·`show` 만 부른다. 결정은 `POST /decide` → 승인 CLI 와 같은 소켓(0700 폴더·0600 파일) → 데몬의 승인 엔진으로 가고, 검증·기록은 엔진만 한다. 화면은 CLI 가 이미 쓰는 신뢰(같은 OS 사용자 + 소켓 권한)를 넘는 권한을 만들지 않는다. `--actor` 가 없으면 `POST` 는 405.
- **누가 결정했나.** 시작 인자 `--actor`(사람 행위자)를 요청마다 `actor` 로 싣는다. 폼 값으로는 바꿀 수 없다. 요청에 `via:'web'` 을 싣는다(자기 신고 값, 감사용).
- **CSRF.** ① 쿠키 `SameSite=Strict`. ② POST 는 `Origin` 이 반드시 있고 `http://127.0.0.1:<포트>` 또는 `http://localhost:<포트>` 이며 `Host` 와 같아야 한다(아니면 403). `Sec-Fetch-Site` 가 있으면 `same-origin` 이어야 한다. ③ 폼마다 1회용 nonce = HMAC-SHA256(세션 키, 버튼|결정 키|지문|발급 시각). 세션 키는 시작 토큰에서 유도하며 메모리에만 있다(다른 실행의 nonce 는 맞지 않는다). 30분 만료, 한 번 쓰면 끝(같은 폼을 다시 보내면 같은 결과로 돌아가고 엔진에는 한 번만 간다). ④ `Content-Type: application/x-www-form-urlencoded` 만(415), 본문 16KB 이하(413), 읽기 5초 제한(408). ⑤ CSP `form-action 'self'`. 스크립트는 없다.
- **낡은 화면 막기.** 폼은 어떤 요청을 보낼지가 아니라 (결정 키, 버튼 이름, 본 내용의 지문, 발급 시각, nonce)만 싣는다. 서버가 POST 때 같은 결정을 읽기 전용 DB 에서 다시 만들어(엔진 `show` 해시 포함) 지문이 같을 때만 보낸다. 보낼 때 `approve` 는 `hash`, `reject`·`cancel`·`request_changes`·`release` 는 `expected_hash`(엔진 대조는 트랙 B)를 싣는다.
- **OTP.** 정책이 재인증을 요구하는 버튼에서만 받고(숫자 6자리), 값은 소켓 요청에만 싣는다. 로그·결과 화면·리다이렉트 주소에 남기지 않는다. 틀린 코드 잠금은 엔진의 기존 잠금(5회, 5분)을 쓰고, 화면은 5분에 5번까지만 OTP 요청을 보낸다.
- **속도 제한.** 화면 프로세스 전체 결정 요청 분당 20건, 넘으면 429.
- **결과 노출.** POST 뒤 `/result/<무작위 id>` 로 303(PRG). 결과는 메모리에 10분, 비밀·OTP 없음.
- **접근 토큰.** 127.0.0.1 이라도 같은 PC 의 다른 프로세스·사용자가 읽을 수 있으므로(DB 0600·소켓 0700 과 같은 수준을 맞추려고) 시작할 때 무작위 32바이트 토큰을 만든다. 토큰이 맞는 요청(상수 시간 비교)은 `HttpOnly; SameSite=Strict; Path=/` 쿠키를 받고 토큰 없는 같은 주소로 303 이동한다. 유효한 쿠키가 없는 그 밖의 요청(그림 파일 포함)은 401 안내 페이지다.
- **127.0.0.1 에만 묶는다.** 다른 주소는 시작할 때 거부한다. Host 헤더가 `127.0.0.1:<포트>` 또는 `localhost:<포트>` 가 아니면 421(DNS 리바인딩 방어). 포트 없는 Host 도 거부.
- **모든 DB 값은 이스케이프 + 비밀 가리기.** HTML 조립(`review-web/html.ts`)의 보간은 기본으로 `maskString`(`@aot/agent-runtime`)을 거친 뒤 이스케이프한다. 마크업으로 넣으려면 `raw()` 를 명시해야 하고 고정 마크업에만 쓴다.
- **응답 헤더**: `Content-Security-Policy: default-src 'none'; img-src 'self'; style-src 'unsafe-inline'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`(`no-referrer` 이면 브라우저가 같은 출처 POST 의 `Origin` 을 `null` 로 보내 출처 확인이 불가능하다. 다른 사이트에는 아무것도 보내지 않는다), `Cache-Control: no-store`, `Cross-Origin-Resource-Policy: same-origin`. 스크립트·외부 CDN·외부 글꼴이 없다(오프라인에서 동작). 폼은 결정 상자의 `POST /decide` 뿐이다.
- **잘림은 늘 보인다.** 긴 값은 비밀 가리기를 먼저 한 뒤 자르고(잘린 비밀 앞부분이 남지 않게) `…(이하 생략: 전체 N자 중 M자만 보인다)` 를 붙인다. DB 의 JSON 은 키 이름 기반 가리기(`maskSecrets`)를 거친 뒤 보인다.
- **엔진이 거절할 결정은 버튼이 아니라 이유가 보인다.** 만료됐거나 기준 버전이 바뀐 조직 제안, 평가 미통과·확인된 증거 없는 상품은 승인 버튼 대신 이유("만료됨", "평가 미통과", "확인된 증거 없음")를 보인다. 판단은 엔진·채널과 같은 함수(`orgProposalStaleness`, `registrationApproveBlocker`)를 쓴다.
- **외부 URL.** 사람이 입력한 값(상품 저장소·환경 주소)만 http/https 링크로 만든다. 에이전트·외부 입력의 URL 은 글자로만 보이고 서버도 가져오지 않는다.
- **SQL**: 요청의 경로·질의는 바인딩 파라미터로만 쓴다(문자열 이어 붙이기 없음).
- **증거 파일 읽기**: 경로가 아니라 **증거 행 id** 로만 찾는다(`/evidence/<id>/file`).
  - 참조 모양: `file:<절대 경로>`(`measure --attach`) 또는 `blob:sha256:<hex>`(근거 저장소).
  - 실경로(심볼릭 링크를 따라간 뒤)가 허용 폴더(근거 저장소 + `--evidence-root`) 안이어야 한다. 파일 시스템 루트는 허용 폴더로 줄 수 없다.
  - 읽은 바이트의 sha256 이 행의 `content_hash` 와 같아야 한다(다르면 거부). **해시가 없는 `file:` 행은 "해시 없음 — 표시하지 않음"** 으로 이름·크기·해시만 알린다. blob 은 파일 이름(=해시)과도 같아야 한다.
  - 파일은 `O_NOFOLLOW` 로 열고(심볼릭 링크 거부), 열린 기술자의 dev/ino 가 먼저 본 값과 같아야 하며, **하드 링크(nlink > 1)는 거부**한다(허용 폴더 안의 이름이 폴더 밖 파일의 다른 이름일 수 있다). 읽기는 기술자로만 한다.
  - 그림만 내보낸다: 앞부분 바이트로 png·jpeg·gif·webp 를 판정해 **그 형식의 Content-Type** 으로 낸다(최대 10 MB). SVG·HTML·그 밖의 파일은 이름·크기·해시만 보이고 내보내지 않는다. blob 텍스트는 이미지 길로 나가지 않는다.
  - 한 번 읽은 바이트로 해시 확인·형식 판정·응답을 모두 한다(검사 뒤 파일이 바뀌는 틈 없음).

## 데모

```
node scripts/review-web-demo.ts            # instance/demo/review.db (gitignore 대상) 를 새로 만든다. 가상 데이터
npm run review-web -- --db instance/demo/review.db     # 터미널에 찍힌 ?token=… 주소를 브라우저로 연다
```

모든 카드 종류가 나온다. 사람이 결정할 거리(조직 제안·고객 메일 초안·게시·정책·실험·상품·전송 여부 …)와 함께, 정책에 위임을 선언해 두어 홈 "AI가 처리함" 요약에만 보이는 일 둘(아직 나가기 전 1건 — 취소 버튼, 이미 나간 1건)도 있다. 일반·위험 조직 제안, 묶인 고객 메일 3건(초안 승인: 외부 입력 영향 1건·기한 지난 1건)·단일 업무, 게시, 정책 변경, 실험 시작·승격·판정 보류, 상품 등록 검토(그림·`<script>` 가 든 외부 입력·해시가 다른 파일·허용 폴더 밖 파일 포함), 전송 여부 불명 효과, 시험 통과·판정 불충분, 신호 제안. "지켜보는 중"에는 시험 중(3/6)·결과 대기 실험·반복 문제 역할이 나온다. 모든 이름·경로는 가상이고 비밀값은 가짜다.

## 하지 않는 것

- 파일이 필요한 결정(정책 배포·조직 재시험·새 역할 제안)을 화면에서 하는 것. 지금은 CLI 로 한다(업로드·입력 폼은 오너 결정 D-A2).
- 위임 범위의 정책 작성·변경(정책 배포는 파일이 필요해 CLI). 화면은 위임을 멈추고 다시 켜고 AI 승인을 취소할 뿐이다. 위임 철회(`delegation revoke`)도 CLI 다.
- 원격 접속, 로그인, 다중 사용자. 이 화면은 이 Mac 의 로컬 전용이다.
- 자동 새로 고침. 화면을 다시 불러 최신 상태를 본다.
