# 공개 저장소 규칙

이 저장소는 공개로 올린다. 시스템의 **설계와 코드**는 공개하고, **운영 인스턴스의 데이터**는 공개하지 않는다.

## 저장소에 두는 것

- 설계 문서, ADR, 스키마(DDL), 상태 머신, 절차 문서
- 코드, 테스트, 마이그레이션
- 정책 **형식**과 가상의 예시 정책 (`policies/` 의 기본값은 안전한 기본 템플릿)
- 가상 데이터: 제품은 `example-product`, 회사·고객·계정도 가상 값만

## 저장소에 두지 않는 것 (`.gitignore` 및 CI 검사 대상)

| 항목 | 이유 |
|---|---|
| 실제 제품명, 로컬 경로, 내부 저장소 주소 | 내부 구성 노출. 제품은 [등록 절차](../products/README.md)로 내부 DB에만 등록 |
| 인스턴스 DB (`instance/`, `*.db`, `*.sqlite*`) | 업무·기억·승인·비용 이력 포함 |
| 비밀값 (API 키, 토큰, `.env`, 키 파일) | 에이전트 컨텍스트에도 넣지 않는다 ([trust-boundaries](trust-boundaries.md) §3) |
| 고객 데이터, 개인정보, 계약·재무 정보 | 기억의 `sensitivity`가 `confidential` 이상인 것 포함 |
| 실제 운영 정책 값(승인자 목록, 예산 한도, 허용 도메인) | 우회 단서가 됨. 인스턴스 설정으로 분리 |
| 에이전트 실행 로그, 작업 인계 메모(`plans/`) | 내부 정보 포함 가능 |
| 전화번호, 통화 기록(transcript)·결과, 녹음, provider 계정 ID(phoneNumberId, assistantId)와 API 키·webhook 비밀 | 개인정보와 비밀. 인스턴스 DB와 환경 변수에만 둔다. 시험·문서는 예약 번호 대역(`+8210000xxxx`, `+82200000xxx`)과 가짜 ID만 쓴다 |
| SQLite 부속 파일(`*.db-wal`, `*-shm`, `*-journal`) | 인스턴스 데이터 |
| 실제 어댑터 실행 로그·녹화 픽스처·스파이크 산출물(`docs/spikes/`)의 원본 | 실제 경로·계정·비용·응답이 섞임. 커밋 전 가상 값으로 치환한 정제본만 둔다 |

## 설정 분리

- 저장소에는 `*.example` 설정만 두고, 실제 값은 `instance/` 아래 또는 환경 변수로 주입한다.
- 정책은 "형식과 기본 템플릿"(저장소)과 "인스턴스 값"(내부)으로 나눈다. 위험 변경 승인 절차(ADR-0006)는 인스턴스 값 변경에도 동일하게 적용한다.

## 공개 전 검사 (CI/수동)

1. 비밀값 스캔 (키 패턴, 고엔트로피 문자열)
2. 금지어 스캔: 내부 제품명·사용자 홈 경로(`/Users/`) 등 인스턴스별 금지어 목록(저장소 밖에 보관)
3. 커밋 이력 검사: 과거 커밋에 내부 정보가 남지 않았는지 (공개 전 첫 커밋부터 깨끗하게 유지)
4. 예시 데이터가 모두 가상인지

## 테스트와 CI

- 실제 에이전트·외부 서비스를 호출하는 테스트는 공개 CI(특히 포크 PR)에서 돌리지 않는다. 비공개 환경에서만 수동/예약 실행하고, 공개 CI는 가짜 어댑터·가짜 도구 테스트만 실행한다.
- 스파이크 산출물과 픽스처는 커밋 전 정제 절차(실제 경로·계정·URL·비용 치환 + 비밀값/금지어 스캔)를 통과해야 한다.

## 주의

- 공개 저장소의 문서·이슈·PR 본문도 외부 입력 경로다. 외부 기여자 콘텐츠를 에이전트 입력으로 쓸 때는 신뢰할 수 없는 입력으로 취급한다.
- 설계 문서에 보안 통제를 공개하는 것은 허용하지만, 통제의 **실제 설정값**은 공개하지 않는다.
